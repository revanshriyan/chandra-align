# Component ablation — does each piece earn its place?

Date: 2026-10-16. Prompt: DeepSeek review asked for an ablation table
(deep vs fallback, each component's contribution). Method: 12-pair
benchmark (ohrc_01–06, tmc2_01–06, 2048×2048 crops) through the deployed
`_align_core`, seed 7, gates frozen. Configs are additive — each adds one
component, so deltas are attributable.

Evidence: `results/table_ablation_2026-10-16.csv` (60 rows).

## The uncomfortable finding, stated plainly

On ohrc_01–05, SIFT+deform reaches SUCCESS_SUBPIXEL — the ceiling. When
the PC or XoFTR arm fires on those same pairs, the verdict drops to
COARSE_ADVISORY (fewer, noisier inliers: e.g. ohrc_01 PC 13 inl vs
SIFT+deform 28). The pipeline uses the first firing opt-in arm's matches
rather than arbitrating arm-vs-fallback quality.

This is not a regression in any deployed configuration: the arms are
**cross-modal specialists**, meant for pairs where SIFT fails, not for
SIFT's home turf. Where SIFT fails, they deliver — XoFTR rescues tmc2_04
(DEGENERATE→COARSE, the only arm to do so on the benchmark), and on the
IIRS windows WildMatch converts N13 DEGENERATE→COARSE (49 inliers,
1.70 px held-out) where base SIFT manages 9 inliers. The PC arm's reason
to exist is the 96-case sun-angle sweep: 10 DEGENERATE→COARSE conversions
at 165–195° azimuth, including the 180° case where SIFT finds nothing.

Known limitation (documented, not fixed today): no arm-vs-fallback
quality arbitration. Fixing it would change default-path behavior;
it stays a documented limitation until a calibrated selector exists.

## LoFTR-family arms on full crops (memory constraint)

On this 7 GB CPU VM, WildMatch / AnyMatch / MatchAnything cannot run the
2048×2048 crops: LoFTR coarse attention needs ~16 GB at that size. The
front-ends fail closed gracefully (return no matches; the run falls back
to SIFT+deform → SUCCESS_SUBPIXEL on ohrc_01). Without a memory cap the
kernel OOM-kills the worker — observed once during this study, which is
why the arm configs were probed rather than fully run. These arms'
evidence stands on the trial harness (smaller windows), e.g.
`docs/wildmatch-trial-2026-10-16.md`. Deployment note: the arms need GPU
or >16 GB RAM at full-crop; the CPU fallback is SIFT.

## Bottom line

- Deform field: the clearest win — 5 COARSE→SUCCESS conversions, zero
  regressions.
- Matcher arms: specialists. They win where SIFT fails (tmc2_04,
  IIRS N13, extreme sun angles) and can underperform SIFT+deform where
  SIFT already succeeds. No arbitration yet — documented.
- Grid bucketing: verdict-neutral on this benchmark; retained for its
  distribution guarantee.

## Appendix: λ-sweep on the OHRC independent pair (negative, 2026-10-16)

What λ is: the TPS **bending-energy weight** of the residual deformation
field (smoothing strength), swept internally per run over
`LAMBDA_GRID = (0.01, 0.03, 0.1, 1.0, 10.0, 100.0)`. It is not a
deep/classical fusion weight and not an entropy term — it regularizes
field curvature only.

Question: the pair sits at 0.5291 px held-out vs the frozen 0.50 px gate;
would a stiffer (or looser) λ close the gap? Pre-registered bar: best
held-out < 0.50 px. Protocol: saved 7069 correspondences, RANSAC
partial-affine sec→ref (298 inliers — exactly the published 238-fit /
60-check split), stage's deterministic 80/20 split, seed fixed, no
re-seeding. Two independent runs: main-agent sweep (stride split, seed 7)
and worker sweep (random 80/20, 5 seeds).

in parentheses where measured):

Seed sensitivity at λ=0.01: 0.5135 / 0.5768 / 0.5682 / 0.5493 / 0.5428 —
all above 0.50. The pipeline's own `apply_deform_field_stage` re-picks
λ=0.01 on the extended grid independently.

Verdict: **clean negative, and informative**. The curve is U-shaped with
the true optimum at λ=0.01 — the default grid already contains it, so no
grid or code change is recommended. λ=0 overfits catastrophically
(in-sample 0.00 px, held-out 0.68 px); stiff λ asymptotes to the
affine-only 1.70–1.84 px. The remaining gap is **not addressable by
deform-field regularization**: λ=0.01 is the held-out argmin and the
default grid already contains it. The leading hypothesis for the residual
is genuine non-projective content (parallax between the 2.5-yr-apart
acquisitions at different processing levels — consistent with the
landmark rerun, where ~60% of the OHRC disagreement was relief parallax);
the measurement is SIFT-based, so pretrained-feature domain gap does not
apply to this pair.

† λ=0 is a single-seed run (seed 7, stride split); the in-sample 0.00 px
is an unambiguous overfit signature, so no replication was deemed
necessary.

Note on baselines: the correct comparator is the pair's published
0.5444 px held-out (same pair, same protocol) — not the 0.1245–0.3697 px
figures, which come from the sun-angle perturbation experiments and
measure something else.

Regression guard: `test_lambda_chosen_by_heldout_not_insample` locks the
stage's selection invariant (λ chosen by internal held-out argmin, never
by inlier fit).
